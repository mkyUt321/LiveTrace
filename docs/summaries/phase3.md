# Phase 3 サマリ(Notion 転記用)

- **日付**: 2026-07-18
- **目的**: 送信元(起点)が毎周期変わる複数バーストを、観測可能な情報のみから同一 actor に束ねる
  再同定エンジンを実装する。経路収束+周期性を主、タイミング相関(Zhang–Paxson系)を実装本体、
  挙動フィンガープリントを補助として組み合わせ、オラクル actor と照合して precision/recall を算出する。

## 環境/バージョン
Phase 0/1/2 と同一。

## 設計判断:「経路収束」に実体を持たせる
仕様の攻撃者モデルは「毎周期ランダムな起点」(単数の攻撃者)。中継についても完全一様ランダムだと、
どのバーストも同じノード母集団から中継を選ぶため、「経路収束」は偶然の重なり以上の意味を持たない
(actor が1つしかない場合、再同定タスク自体も自明になりがち)。
そこで **`AttackerCampaign` に private relay pool を追加**した: 各 actor はネットワーク全体から
`relay_pool_fraction`(既定0.35)の乱数部分集合を自分専用の中継候補として持ち、**起点は毎回全ノードから
自由に選ぶ(仕様通り)が、中継ノードはこの private pool からのみ選ぶ**。これは実際の踏み台攻撃で
「侵害済みホストの限られたプールを使い回す」ことを模した、現実的かつ正当化可能な拡張であり、
これによって初めて「経路収束」が本物の識別信号になる。また、単一 actor がデフォルト(`attacker.count: 1`、
仕様に忠実)のままでも、この private pool の仕組み自体は温存され将来の拡張(複数 actor)に使える。
Phase 3 の評価では **actor 数を2に設定した専用テスト構成**を使用(default.yaml のプロジェクト既定値は
単一 actor のまま変更していない)。

## 実装
- `ReidentificationEngine`(`contrib/livetrace/model/reidentification-engine.*`):
  `TracebackObserver` の trace 完了通知(`SetTraceCompleteNotify`、Phase2で追加)を受け取り、
  完了した各バーストを既存 actor クラスタに割り当てるか、新規クラスタを起こす。
  - **周期性**: クラスタの推定周期(初回は `attacker.period_s` を事前分布として使用、以降は
    観測間隔から指数移動平均で更新)に対する新バーストの検知時刻のズレをスコア化
    (最大3周期分の欠測を許容)。
  - **経路収束**: 新バーストの中継ノード集合とクラスタが過去に見た中継ノード集合の Jaccard 類似度。
  - 上記2つを内部で 0.7(周期性)/0.3(収束)で合成した「主スコア」とする
    (周期性は本シミュレーションでは決定論的に近く最も信頼できる信号であるため優先)。
  - **タイミング相関**(実装本体): victim直近フローの ON/OFF 信号を、クラスタの基準バーストと
    `TimingCorrelator::Correlate` で比較(Phase1/2と同じ相関エンジンを再利用)。
  - **フィンガープリント**(補助): 平均 ON 継続長・遷移回数の類似度。
  - 合成スコア = `periodicity_weight`(0.40)×主スコア + `timing_weight`(0.45)×タイミング + 
    `fingerprint_weight`(0.15)×フィンガープリント。`cluster_score_threshold`(0.5)以上で
    既存クラスタに割当、それ未満なら新規クラスタを起こす(actor数を事前に与えない)。
  - 出力は `results/reid_*.jsonl`(システム出力、真の actor_id は一切参照しない)。

## 遭遇した不具合とチューニング
- 初期の重み付け(周期性/収束を単純 0.5/0.5 平均)では、収束スコアが中程度(ランダム抽出プールの
  部分重複により 0.3〜0.4 程度)になるケースで、周期性がほぼ完璧(スコア≈1.0)でも合成スコアが
  閾値 0.55 を下回り、同一 actor のバーストが複数の偽クラスタに分裂した(小規模テストで実際に発生を確認)。
  → 内部合成比を 0.7(周期性)/0.3(収束)に変更し、`cluster_score_threshold` を 0.55→0.5 に調整。
  再テストで2 actor・10周期がそれぞれ正しく単一クラスタに収束することを確認。

## 評価(`analysis/evaluate_phase3.py`, ペアワイズ precision/recall)
- テスト構成: n=20, p=0.25, **attacker.count=2**(周期40秒、位相はランダムでずらす)、
  chain_length 2〜4、relay_pool_fraction 0.35、10 seed × 400秒 = seed あたり20バースト(actor毎10)。
- **ペアワイズ精度(seed毎平均±95%CI)**: 0.937 ± 0.104
- **ペアワイズ再現率(seed毎平均±95%CI)**: 0.833 ± 0.123
- 単体テスト(`ReidentificationEngineTestCase`)でも、周期・位相・中継プールが異なる2 actor の
  合成バーストが正しく2クラスタに分離されることを確認(全6ユニットテスト PASS)。

## 考察
- 小規模(N=20)でもクラスタリングは完璧ではなく(precision/recallとも1.0未満、CI幅も比較的広い)、
  これは Phase1/2の単一ホップ相関・多ホップ遡上が小Nでほぼ完璧だったのと対照的。
  再同定は「ランダムに重なる中継プール」「周期性推定のコールドスタート(初回検出時は事前分布に依存)」
  など、Phase1/2にはなかった追加の不確実性源を持つため、精度に幅が出るのは妥当な結果と考える。
  Phase4の規模スイープでこの傾向(Nが増えると精度がどう変化するか)を継続観察する。
- 周期性を主スコアの中で優先した設計判断(0.7/0.3)は、本シミュレーションの攻撃者が
  ジッターのない厳密な周期で発火するために有効に機能した。実際の攻撃者はより不規則な周期を
  持つ可能性があり、その場合はタイミング相関・フィンガープリントの重みを上げる必要が出るかもしれない
  ——この重み付けはハイパーパラメータであり、今後のスイープで感度を確認する余地がある。
