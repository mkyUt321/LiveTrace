# Phase 1 サマリ(Notion 転記用)

- **日付**: 2026-07-18
- **目的**: Zhang–Paxson 型 ON/OFF タイミング相関で、victim への到達フローから直上流 1 ホップを
  生きた窓内にオンラインで確定する。正常背景がある小 N で誤検出(ノイズ)との分離を平均±95%CIで確認する。

## 環境/バージョン
Phase 0 と同一(ns-3-dev 3.48 debug, WSL Ubuntu 24.04, g++13.3, Python 3.12.3)。

## 実装
- `TimingCorrelator`(`contrib/livetrace/model/timing-correlator.*`): フローの ON/OFF 信号を
  `bucket_s`(既定 0.05s)刻みでビン化(パケットレートが `on_threshold_pps` を超えるビンを ON=1)。
  2信号間のスコアは `max_lag_buckets` の範囲でラグ探索した最良ピアソン相関係数。
  `min_on_off_transitions` 未満の遷移しかない信号(フラットすぎる)は自動的にスコア -1 で棄却。
  `FindBestUpstreamMatch`: あるノードで「そのノードが受信側」であるフロー群(候補)の中から、
  既知の確定フロー(例: 直近relay→victim)と最もよく相関するものを探す。
- `TracebackObserver`(`contrib/livetrace/model/traceback-observer.*`): victim の新規フロー到着を
  フックし、`accumulation_delay_s` 待って(パターンを少し貯めてから)直上流ノードのアドレスを解決し、
  そのノードの受信側候補フローに対して 1 ホップだけ相関探索を実行、結果を
  `results/traceback_*.jsonl` に記録(システム出力、オラクルとは別)。Phase 1 では `max_hops=1` に固定
  (再帰は Phase 2 で追加)。オラクルには一切アクセスしない。
- 公開トポロジ情報として `results/topology_*.jsonl`(node_id↔IPアドレス、複数インタフェース全て)を出力。
  これは真値ではなく実運用のホスト台帳に相当。

## 遭遇した不具合と修正
1. **ON/OFF 信号の分解能不足**: 当初の攻撃パケット生成は 2〜4 個の大きなサブバースト(間隔 1.5秒超)
   だったため、`accumulation_delay_s=1.0s` 以内には遷移が1回しか入らず、
   `min_on_off_transitions=3` を満たせず全候補が棄却された(全試行が `no_match_above_threshold`)。
   → サブバースト数を 5〜8、アイドルギャップを 0.15〜0.4秒に短縮し、`packets_per_burst` を 40→80、
   `accumulation_delay_s` を 1.0→2.0秒に調整。生きた5秒窓の予算(Phase2でのマルチホップ再帰に必要)を
   圧迫しない範囲で、相関に必要な遷移数を早期に確保できるようにした。
2. **NodeAddressIndex/トポロジマップが最初のインタフェースしか登録していなかった**: 次数2以上の
   ノードは辺ごとに複数の IP を持つが、当初は `GetAddress(1,0)` のみを登録していたため、
   実際の送信元アドレスが2本目以降の辺のものだと解決に失敗する(誤って別ノードだと誤認しうる)
   可能性があった。全インタフェースを登録するよう修正し、`results/topology_*.jsonl` にも全アドレスを出力。
   小N実データで検証し、2バーストとも直上流ノードの解決が真の連鎖と一致することを確認。
3. **開発環境のツール不具合(参考)**: WSL 経由のシェルコマンドで `wsl -d Ubuntu -- bash -lc '...'` に
   複数行/変数展開を含めると `$var` が空になる現象に遭遇(引数受け渡しの引用符処理の問題と推測)。
   スクリプトファイルを作成し `MSYS_NO_PATHCONV=1 wsl -d Ubuntu -- bash <script>` の形で実行することで回避
   (Git Bash が Unix風パスを Windows パスに変換してしまう問題も合わせて解消)。

## 評価(`analysis/evaluate_phase1.py`, `analysis/correlator.py` でオフライン再実装し照合)
- 小 N (n=12, p=0.3), 周期40秒・バースト5秒(試験用に短縮)、10 seed × 200秒 = seed あたり約5バースト、
  計 50 バーストで評価。
- **単一ホップ再現率(seed毎の平均±95%CI)**: 1.000 ± 0.000 (10 seeds)
- **単一ホップ適合率(プール)**: 1.000 (50/50 の "matched" 出力が真の直上流ノードと一致)
- **真候補 vs 最良ノイズ候補のスコア差(平均±95%CI)**: 1.874 ± 0.038 (n=15; 両方の候補が観測された
  バーストのみ)— 真の一致が常にノイズを明確に上回りスコアで分離できることを確認(Phase1の受入基準を満たす)。

## 考察
- 小 N ではノイズ(背景トラフィック)と真の連鎖が同じノードに同時に現れるケースが限定的(15/50)。
  Phase 4 の規模スイープでは N が大きくなるほど各中継ノードを通過する無関係フロー数が増えるため、
  スコア差の分布がどう変化するかを継続的に観測する必要がある。
- ON/OFF 相関のタイムスケール(サブバースト間隔・アイドルギャップ)は生きた5秒窓・累積遅延2秒という
  予算と直接トレードオフの関係にある。Phase 2 でホップ数を増やすと、各ホップに割ける累積時間が
  さらに短くなるため、この相関タイムスケール設計は今後も要注意ポイント。
